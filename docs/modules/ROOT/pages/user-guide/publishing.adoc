= Publishing

A dashboard is published as soon as an editor saves it: everyone who can sign in to NeoDash
finds it in the list of dashboards. There is no separate viewer deployment to set up; what
people can do depends on the role they have in your identity provider.

[cols="1,3",options="header"]
|===
|Role |What they can do
|Viewer |Open dashboards and use them: switch pages, set parameters and filters, follow report
actions, maximise reports. Reports run only the queries saved in the dashboard, read-only; viewers
can't see or change the queries, and can't save.
|Editor |Everything viewers can, plus create, edit, save, import, export and delete dashboards,
and run any Cypher query from a report's editor.
|===

A user without either role is turned away after signing in. Your administrator assigns the
roles (for example as Keycloak realm roles); see
link:../../developer-guide/roles-and-security[Roles, Security & Audit].

== Building and publishing

Editors change a dashboard in place. Changes stay in your browser as a *draft* (the header shows
*Unsaved changes*) until you click *Save*; only then do viewers see them. To try out larger changes
without affecting viewers, export the dashboard, import it as a new one, and work on the copy.

== Presentation mode

The dashboard setting *Editable* (see link:../dashboards#_dashboard_settings[Dashboard Settings])
turns off editing in the dashboard for editors too, which is useful while presenting. Viewers can
never edit, whatever this setting says.

== Sharing

Every dashboard has its own address, including the page and the parameter values in use, so you
can share it as a link; see link:../dashboards#_share_a_dashboard[Share a Dashboard]. Whoever opens
the link signs in first, and their role decides what they can do.
