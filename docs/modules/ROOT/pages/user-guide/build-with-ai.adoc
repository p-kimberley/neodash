= Build with AI

Let a language model help you build reports, from your database's schema and your dashboard:

* *Build with AI* in an empty report builds the whole report (type, title, query, fields and settings) from a description, or from one of up to three suggestions.
* *Ask AI* in a report's settings changes the report as you describe.
* If you only want help with queries, write a report's query as a question in English and have it translated to Cypher; you set up the rest of the report yourself.

Build with AI is part of NeoDash: it is available in every dashboard when the server has a language model configured, and absent when it hasn't.

== Building a report

A new report (or any report without a query) shows two buttons: *Configure*, which opens its settings, and *Build with AI*.

. Click *Build with AI*. Up to three options appear, based on your data and the dashboard (its title, pages, parameters and other reports, which they avoid repeating).
. Or describe the report you want, for example "revenue per month as a line" or "top 10 products as horizontal bars with a legend". Press Enter (or click the sparkles button in the box) and up to three options for it appear; the first is the one recommended. Typing alone doesn't ask, so nothing loads until you're ready. The box starts one line high and grows as you write; Shift+Enter starts a new line.
. While the options are worked out, a ring of colour circles the box and the sparkles button becomes *Stop*. Click it (or press Escape) to stop: the NeoDash server stops too, and the options you had before come back.
. Each option shows a small preview drawn from its data, a plain description of what it creates (the kind of chart, what is on each axis, how it is coloured), and a note on any settings it sets (for example "Bars run sideways. A legend is shown."). Click one to build it.
. The report is built and runs. It is not saved until you save the dashboard, and the message that confirms it has *Undo*.

To change a report later, click *Edit*, then *Change with AI* (beside the report's type and database), and describe the change, for example "make it a stacked bar chart by region" or "show a legend". Options for the change appear the same way; click one to apply it. *Save* keeps it, *Cancel* (or *Undo*) puts the report back.

== What is checked

Nothing the model writes is used until it has been checked. The NeoDash server checks:

* that it describes a report type the dashboard has, with every field the type needs, and only settings that type has, with allowed values;
* the query, with `EXPLAIN` (which never runs or changes anything): it must be valid Cypher, must only read, and must use labels, relationship types and properties that exist;
* a short trial run of the query, which only reads, stops after a few seconds and at most 25 rows: it should return rows (a report that still returns none after the model has been told is kept, with a note), and the columns for the report's fields must exist and hold the right kind of value (numbers for a bar chart's values, dates or numbers for a line chart's x axis, and so on). Reports without fields are checked on what they draw: a graph must get nodes or relationships, a map nodes with coordinates, and a Sankey diagram relationships with the numeric property that sizes its flows (or flows of equal width).

Each problem goes back to the model with what is allowed (the report types, the settings' values, the columns the query returns, or the closest existing label, as in "did you mean `Customer`?"), and it tries again, up to four times by default. A report that is still wrong is not applied; you see what was wrong instead. Settings that are still wrong at the end are left out.

== How it works (writing a query in English)

The language model is set up for the NeoDash server by an administrator: any model served through an OpenAI-compatible API, such as https://docs.vllm.ai[vLLM] in your cluster. Browsers never connect to it, and no API key is entered in NeoDash itself.

When an editor translates a question, the NeoDash server:

. reads the database schema (node labels, relationship types, property names and how they connect), with APOC if it is installed and with Neo4j's built-in schema procedures if not;
. sends the model the schema, the question, the report's earlier questions, the dashboard's example questions and the shape of result the report type needs;
. checks the model's query against the database with `EXPLAIN`, which never runs or changes anything; if the check fails, it gives the model the error and lets it try again;
. returns the checked query, which replaces the report's query.

Query results are never sent to the model. Questions, descriptions and the queries they produce are recorded in the audit log.

== Setting it up (administrators)

With the Helm chart, set the model's address and name, and optionally an API key from a Secret:

[source,yaml]
----
ai:
  baseUrl: http://vllm.ai.svc:8000/v1
  model: Qwen/Qwen2.5-Coder-32B-Instruct
  apiKey:
    existingSecret: llm-api-key   # optional; key "api-key"
----

Without the chart, set `AI_BASE_URL`, `AI_MODEL` and, if needed, `AI_API_KEY_FILE` on the server. Both the address and the model name are needed; the server won't start with only one of them. To turn Build with AI off while keeping these settings, set `ai.enabled: false` (`AI_ENABLED=false`). With a network policy, allow the pods to reach the model. Models trained on code and Cypher give the best results.

== Writing a query in English

. Open a report's settings, and switch its query editor from *Cypher* to *English*.
. Write your question, then click *Translate*. After a few seconds the query appears in the Cypher editor, where you can check and change it before running the report.

Only editors can translate questions, because the query is then run like any query an editor writes.

== Better answers

Descriptions that name the node labels, relationship types and properties to use get better results, for example "Which *Customer* nodes *PLACED* more than 10 *Order* nodes?".

Dashboards saved with example questions (questions with the queries that answer them, which earlier versions let you edit) still send them to the model with every question; they help it use your own labels and properties.
