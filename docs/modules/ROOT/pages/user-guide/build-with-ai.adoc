= Build with AI

Describe what a report should show in plain language, and let a language model write its query, using your database schema and the type of report.

Build with AI is part of NeoDash: it is available in every dashboard when the server has a language model configured, and absent when it hasn't.

== How it works

The language model is set up for the NeoDash server by an administrator: any model served through an OpenAI-compatible API, such as https://docs.vllm.ai[vLLM] in your cluster. Browsers never connect to it, and no API key is entered in NeoDash itself.

When an editor builds a report with AI, the NeoDash server:

. reads the database schema (node labels, relationship types, property names and how they connect), with APOC if it is installed and with Neo4j's built-in schema procedures if not;
. sends the model the schema, the description, the report's earlier descriptions, the dashboard's example questions and the shape of result the report type needs;
. checks the model's query against the database with `EXPLAIN`, which never runs or changes anything; if the check fails, it gives the model the error and lets it try again;
. returns the checked query, which replaces the report's query.

Query results are never sent to the model. Descriptions and the queries they produce are recorded in the audit log.

== Setting it up (administrators)

With the Helm chart, set the model's address and name, and optionally an API key from a Secret:

[source,yaml]
----
ai:
  baseUrl: http://vllm.ai.svc:8000/v1
  model: Qwen/Qwen2.5-Coder-32B-Instruct
  apiKey:
    existingSecret: llm-api-key   # optional; key "api-key"
----

Without the chart, set `AI_BASE_URL`, `AI_MODEL` and, if needed, `AI_API_KEY_FILE` on the server. Both the address and the model name are needed; the server won't start with only one of them. To turn Build with AI off while keeping these settings, set `ai.enabled: false` (`AI_ENABLED=false`). With a network policy, allow the pods to reach the model. Models trained on code and Cypher give the best results.

== Using it

. Open a report's settings, and switch its query editor from *Cypher* to *Build with AI*.
. Describe what the report should show, then click *Build*. After a few seconds the query appears in the Cypher editor, where you can check and change it before running the report.

Only editors can build with AI, because the query is then run like any query an editor writes.

== Better answers with example questions

Example questions, with the queries that answer them, are sent to the model with every description in the dashboard. Examples that use your own labels, relationship types and properties make its queries noticeably more accurate.

To add them, click the *Build with AI* button in the dashboard header (editors see it when the server has a model; it also shows which model is used), then *Example questions*. They are saved with the dashboard.

Descriptions that name the node labels, relationship types and properties to use also help, for example "Which *Customer* nodes *PLACED* more than 10 *Order* nodes?".
