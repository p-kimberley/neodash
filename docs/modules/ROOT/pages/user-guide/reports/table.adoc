
= Table

The most common report in a dashboard is often a simple table view.
NeoDash contains a powerful table component that can render all the data
returned by a Cypher query. This includes simple data like numbers or
text, but also Neo4j native data like nodes, relationships, and paths.

The table report supports the following additional features:

- Pagination. The rows-per-page menu below the table changes how many rows are shown; the choice is remembered in your browser for that report.
- Sorting, by clicking a column's header.
- Filtering: open a column's menu (the button in its header) and choose *Filter...*, then type the text to look for. A funnel icon marks filtered columns. The same menu also sorts the column.
- Prefixing a column header with __ (double underscore) hides the column.
- Downloading your data as a CSV file.

Values that don't fit on one line are cut off with an ellipsis, unless *Wrap overflowing content* is on.
Double-clicking a table cell copies its value to the clipboard.

== Examples

=== Basic Table

....
MATCH (n:Movie)<-[:ACTED_IN]-(p:Person)
RETURN n.title AS Title, n.released AS Released, count(p) as Actors
....

image::table1.png[Basic Table]

=== Table with nodes / collections

....
MATCH (n:Movie)<-[:ACTED_IN]-(p:Person)
RETURN n, collect(p.name) as actors LIMIT 200
....

== Advanced Settings

[width="100%",cols="12%,6%,26%,56%",options="header",]
|===
|Name |Type |Default Value |Description
|Rows per page |Number |25 |The number of rows shown per page. Viewers can pick another number below the table; their choice is remembered in their browser until this setting changes.

|Transpose Rows & Columns |on/off |off |When activated, transposes the
rows and columns of the table. This means that each of the returned rows
from Neo4j will be shown as a column instead of a row.

|Compact Table |on/off |off |When activated, shows the rows at a smaller height (32px).

|Wrap overflowing content |on/off |off |When activated, long values wrap onto several lines, between words where possible (a word longer than the column is broken). Otherwise each row is one line high and long values end in an ellipsis.

|Column Widths Specification |Relative (%) / Fixed (px) |Relative (%) |How *Relative/Fixed Column Sizes* is read: as relative weights, or as widths in pixels. Relative widths always fill the table's width. While editing a dashboard, you can drag the edge of a column's header to resize it: this switches the report to *Fixed (px)* and saves the new widths in *Relative/Fixed Column Sizes*. Viewers can drag the columns of a fixed-width table too, but their changes aren't saved.

|Relative/Fixed Column Sizes |List of numbers |1, 1, 1, … |The width of each column, as a comma-separated list in the order the query returns them (hidden `__` columns included). With relative widths, if the
first column should be twice the width of the 2nd and 3rd, this will be
set to `2, 1, 1` (percentages such as `50%, 25%, 25%` work the same way). With fixed widths, the numbers are pixels, e.g. `200, 100, 100`. Brackets are optional (`[2, 1, 1]` also works), and columns left out get the default width. A fixed width is at least 40px.

|Enable CSV Download |on/off |off |When activated, displays a button in
the table footer. This button lets the user download
the complete set of table results (all pages) as a CSV file.

|Override no data message |Text |Query returned no data. |Override the message displayed to the user when their query returns no data.

|Auto-run query |on/off |on |When activated, automatically runs the query
when the report is displayed. When set to off, the query is displayed
and will need to be executed manually.

|Selector Description |Markdown text | |When specified, adds a button to the report header that opens a pop-up with the rendered markdown from this setting.
|===

== Rule-Based Styling

Using the xref:user-guide/extensions/rule-based-styling.adoc[Rule-Based Styling] menu, the
following style rules can be applied to the table: 

- The background color of an entire row in a table. 
- The text color of an entire row in a table. 
- The background color of a single cell in the table. 
- The text color of a single cell in the table.

If a column is hidden (header prefixed with __ double underscore), it can still be used as an entry point for a styling rule.

== Report Actions

With the xref:user-guide/extensions/report-actions.adoc[Report Actions] extension, tables can be turned into interactive components that set parameters.
Two flavours of report actions for tables exist:

=== 1. Select a value from a row
Adding a **Cell Click** action to a table column, turns the values in that row into clickable buttons.
When the user clicks on the button, a predefined parameter is set to one of the columns in that row.

image::select-single-table.png[Select a value from a table to be used as a parameter]

=== 2. Select multiple from a row
Adding a **Row Clicked** action to a table prepends each row with a checkbox.
The user can then check one or more boxes to update a dashboard parameter.

> Keep in mind that regardless if one or more values are selected, the type of the dashboard parameter is a list of values. The queries using the parameter must ensure that the list type is handled correctly.

image::select-multiple-table.png[Select multiple values to be used as a parameter]
