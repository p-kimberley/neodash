
= Reports

A report is the smallest building block of your dashboard. Each report
will have a single Cypher query behind it that is used to populate the
report. Reports can be of several types (graph, table, bar chart, etc.),
each of which expect different types of data. See the relevant
documentation pages for more information.

A report can be given a title, which is displayed at the top of the report.
To change the query of a report, open its settings by clicking
the cog icon on the top right of the report (editors only).
Every report also has a maximise button next to it, which shows the report
over the whole window; Escape or a click outside it restores it.

image::report.gif[Report]

The settings window additionally allows you to change the type of
report, the refresh rate of the report, and a number of *Advanced
Settings*. The advanced settings differ between the different report
types, and can be viewed by turning on the *Advanced settings* switch at the bottom of
the settings.

== Create and Delete Reports

A new report can be added to a page by clicking the large (+) button at
the end of the page. By default, a report will have nothing defined, so
you will need to set the query before any data is visualized.

Reports can be deleted by opening the report settings, and clicking the
bin icon at the top of the report. The icon next to it clones the report.

== Re-order Reports

Reports can be re-ordered by dragging and dropping
them around the page. To move a report, grab it by the handle (top left
corner), and drag it to the desired location.

image::movereport.gif[Report]

== Resize Reports

Reports can be resized by grabbing their bottom-right
corner, and dragging your mouse to the desired size.

== Writing Queries

A single Cypher query is used to populate each report. Any Cypher
syntax is supported, including procedures from plugins installed in your
database, such as APOC or Graph Data Science.

Queries run on the NeoDash server, not in your browser. Editors can run any
query while writing a dashboard. Viewers only run the queries saved in the
dashboard, and only to read data: a query that writes to the database fails
for a viewer. Each query is stopped after its time limit (the dashboard's
*Maximum Query Time* setting, at most the server's maximum).

Keep the following best practises in mind when writing your Cypher
queries: 

1. Always use a `LIMIT` in your query to keep the result size
manageable. 
2. Ensure you return the right data types for the right
report type. For example, a graph report expects nodes and
relationships, whereas a line chart expects numbers.

== Row Limiting

NeoDash has a built-in *row limiter*. This means that results
are truncated to a maximum number of rows, depending on the report type
(and never more than the server's maximum).
The row limiter is in place to ensure that visualizations do not become
too complex for the browser to handle.

Note that rows are only limited after the query is executed. For this reason, it is
recommended to use the `LIMIT` clause in your query at all times.

== Parameters

Parameters can be set in a dashboard by using a link:parameter-select[Parameter Select] report. Set parameters are then available in any Cypher query across the dashboard.

In addition, these **session parameters** are always available:

|===
|Parameter | Description
| $session_uri | The address of the NeoDash server, e.g. `https://neodash.example.com`.
| $session_database | The server's default Neo4j database.
| $session_username | The username of the signed-in user.
|===
