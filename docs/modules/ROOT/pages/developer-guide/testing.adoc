= Testing

== Browser tests

`dev/e2e` holds a https://playwright.dev/[Playwright] suite that drives the real app against the xref:developer-guide/build-and-run.adoc[dev stack]: it signs in through Keycloak as `editor` and `viewer`, and checks every report type on the example dashboards, the dashboard list and panel, maximised reports, tables, editors, interactions, the in-app docs and Text2Cypher, in both light and dark appearances.

It runs in Playwright's Docker image, so only Docker is needed. Start the dev stack, and the dev server to test changes that aren't built into the image yet, then:

[source,sh]
----
dev/e2e/run.sh                                  # against the dev server, http://localhost:5173
APP_URL=http://localhost:3000 dev/e2e/run.sh    # against the backend container (production build)
dev/e2e/run.sh --project=dark tests/maximise.spec.mjs   # other arguments go to `playwright test`
----

A full run takes about ten minutes. Results are in `dev/e2e/report/index.html`, with a screenshot and a trace for each failure. Every test also fails on errors in the page.

Tests that change a dashboard save a temporary copy under a `dddd0000-…` id and delete it afterwards. Helpers for opening pages, finding reports and saving dashboards are in `dev/e2e/tests/helpers.mjs`.

Inside its container, the browser reaches the dev stack on the host through a small relay (`dev/e2e/global-setup.mjs`), so it uses the same `localhost` addresses as the backend's sign-in settings.

== Backend tests

The backend's tests use https://vitest.dev/[Vitest]:

[source,sh]
----
cd server
npm test                   # unit tests
npm run test:integration   # the API against the dev stack's Neo4j
npm run test:e2e           # real sign-in through Keycloak, against the backend in the dev stack
----

The integration and sign-in tests need the dev stack running.

== Checks on every push

The GitHub Actions workflow `.github/workflows/neodash.yml` runs the backend's type check and tests (with a Neo4j Community service), ESLint and a production build of the UI, and lints and validates the Helm chart, before building the image.

`yarn lint` (ESLint) and `yarn format` (Prettier) check and format the code by hand. `yarn hooks` turns on a pre-commit hook that does both for the files being committed.

== Debug report

For ad-hoc testing, NeoDash can download a JSON copy of its current state: open *About* from the Help menu in the header and click *Debug Report*.
