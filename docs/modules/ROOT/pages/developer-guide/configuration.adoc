= Configuration

NeoDash is configured on the server: the backend reads environment variables at start-up, and the Helm chart sets them from its values. Nothing is configured in the browser.

Secrets can be given as files instead of values, by setting `<NAME>_FILE` (`NEO4J_PASSWORD_FILE`, `OIDC_CLIENT_SECRET_FILE`, `SESSION_SECRET_FILE`, `AI_API_KEY_FILE`), or `NEO4J_AUTH_FILE` containing `user/password`. The chart mounts every secret as a file.

== Settings

[cols="3,3,2,5",options="header"]
|===
|Variable |Helm value |Default |

4+|*Server*
|`PUBLIC_URL` |`publicUrl` |required |The address users open NeoDash on; used for sign-in redirects, cookie security and the same-origin check.
|`ADDITIONAL_ORIGINS` |– |– |Other origins the UI is served from, e.g. `http://localhost:5173` for the dev server.
|`TRUST_PROXY` |set when the Ingress or HTTPRoute is enabled |`false` |Trust `X-Forwarded-For`, so audit lines record the client's address.
|`STATIC_DIR` |set by the image |– |The built UI to serve.
|`PORT` / `HOST` / `LOG_LEVEL` |`logLevel` |`3000` / `0.0.0.0` / `info` |

4+|*Neo4j*
|`NEO4J_URI` |`neo4j.uri` |`neo4j://localhost:7687` |
|`NEO4J_USERNAME` / `NEO4J_PASSWORD` |`neo4j.auth.existingSecret` |`neo4j` / required |
|`NEO4J_DATABASES` |`neo4j.databases` |`neo4j` |Databases reports may query; the first is the default. Community edition has only `neo4j`.
|`DASHBOARD_DATABASE` |`neo4j.dashboardDatabase` |the first database |Where the `_Neodash_Dashboard` nodes are.

4+|*Sign-in (OpenID Connect)*
|`OIDC_ISSUER_URL` |`oidc.issuerUrl` |required |The issuer as browsers and tokens see it.
|`OIDC_DISCOVERY_URL` |`oidc.discoveryUrl` |the issuer |Where the backend reads the provider's metadata, if different (e.g. an in-cluster address).
|`OIDC_CLIENT_ID` / `OIDC_CLIENT_SECRET` |`oidc.clientId` / `oidc.existingSecret` |required |A confidential client; its redirect URI is `PUBLIC_URL/auth/callback`.
|`OIDC_SCOPES` |`oidc.scopes` |`openid profile email` |
|`OIDC_ROLES_CLAIM` |`oidc.rolesClaim` |`realm_access.roles` |Dot path to the roles in the token, e.g. `resource_access.neodash.roles` for client roles.
|`OIDC_USERNAME_CLAIM` |`oidc.usernameClaim` |`preferred_username` |
|`ROLE_VIEWER` / `ROLE_EDITOR` |`oidc.roles.viewer` / `.editor` |`neodash-viewer` / `neodash-editor` |
|`OIDC_ALLOW_INSECURE_HTTP` |`oidc.allowInsecureHttp` |`false` |Only for a local `http://` identity provider.
|`NODE_EXTRA_CA_CERTS` |`oidc.caBundle` |– |Extra certificate authorities, for an identity provider or `neo4j+s://` server with an internal CA.

4+|*Sessions*
|`SESSION_SECRET` |generated, or `session.existingSecret` |required |At least 32 characters; encrypts the session cookie. Changing it signs everyone out.
|`SESSION_MAX_AGE_SECONDS` |`session.maxAgeSeconds` |`28800` (8 hours) |Roles are read again at the next sign-in.

4+|*Queries and audit*
|`QUERY_TIMEOUT_SECONDS_DEFAULT` / `_MAX` |`query.timeoutSecondsDefault` / `query.timeoutSecondsMax` |`20` / `120` |A report's time limit is capped at the maximum.
|`QUERY_ROW_LIMIT_MAX` |`query.rowLimitMax` |`10000` |Rows beyond this aren't fetched; the report says the result was cut short.
|`AUDIT_LOG_PARAMETERS` |`audit.logParameters` |`true` |Include parameter values in audit lines.

4+|*Maps*
|`MAP_TILE_URL` / `MAP_TILE_ATTRIBUTION` |`maps.tileUrl` / `maps.tileAttribution` |– |Background tiles for map reports, e.g. from an internal tile server. Empty: no tiles, so nothing is fetched from the internet.
|`MAP_DATA_URL` |`maps.dataUrl` |`/maps` |Where choropleth and area maps load country and region shapes from; by default, from the image itself.

4+|*Build with AI*
|`AI_BASE_URL` |`ai.baseUrl` |– |An OpenAI-compatible API (`<base>/chat/completions`), e.g. vLLM at `http://vllm.ai.svc:8000/v1`. Empty: Build with AI is off.
|`AI_MODEL` |`ai.model` |– |The model name the API serves; required with the address.
|`AI_ENABLED` |`ai.enabled` |`true` |Turns Build with AI off while keeping the model settings.
|`AI_API_KEY` |`ai.apiKey.existingSecret` |– |Optional; sent as a bearer token.
|`AI_TIMEOUT_SECONDS` |`ai.timeoutSeconds` |`60` |Per request to the model.
|`AI_MAX_ATTEMPTS` |`ai.maxAttempts` |`2` |Answers per request: each is checked with `EXPLAIN`, and a failed one is retried with the error.
|`AI_TEMPERATURE` / `AI_MAX_TOKENS` |`ai.temperature` / – |`0` / – |
|`AI_SCHEMA_TTL_SECONDS` |– |`300` |How long a database's schema, which is sent to the model, is reused.
|===

Variables without a Helm value can be set through `extraEnv`. Product name, logo and colours are set separately: see xref:developer-guide/style-configuration.adoc[Style Configuration].

== From upstream NeoDash

Upstream NeoDash was configured in the browser, through `config.json` or environment variables of its nginx image: `ssoEnabled`, `standalone`, `standaloneHost`, `standaloneDashboardName` and so on. None of these apply here:

- Sign-in is always through the OpenID Connect provider, and the backend holds the Neo4j credentials.
- Standalone (reader) mode is replaced by the viewer role, in the same deployment as editors: see xref:developer-guide/roles-and-security.adoc[Roles, Security & Audit].
- Users choose a dashboard on the start page or in the dashboards panel, and every dashboard has its own URL, instead of one fixed dashboard per deployment.
- User activity is recorded in the audit log on stdout, not in a Neo4j database.
