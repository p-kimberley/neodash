= Style Configuration

The product name, logo and colours are set per deployment, with the Helm chart's `branding` values:

[source,yaml]
----
branding:
  appName: Acme Insights         # in the header and the browser tab
  logo:
    base64: ''                   # set with --set-file branding.logo.base64=logo.b64
    fileName: logo.svg
  style:
    --theme-light-color-primary-bg-strong: '#005eb8'
    --theme-dark-color-primary-bg-strong: '#78b4ff'
----

- `appName` replaces "NeoDash" in the header and the browser tab; the header's mark shows its initials.
- `logo` replaces the mark with your logo, a PNG or SVG file encoded as base64 (`base64 -w0 logo.svg > logo.b64`). It's served from the pod, so it works offline.
- `style` overrides colours of the Neo4j design system, per appearance: any `--theme-light-color-…` or `--theme-dark-color-…` token (see the https://neo4j.design/[design system's] colour tokens). The names used before NeoDash 4 (`--palette-light-…` / `--palette-dark-…` with `"R, G, B"` values) still work.

Changing these values restarts the pods. Users choose a light, dark or system-matching appearance themselves, from the header; their choice is kept in their browser.

== Without the chart

The chart writes these settings to `style.config.json`, which the app reads at start-up from its own address (`/style.config.json`, in the image at `/app/public/style.config.json`), with the logo next to it:

[source,json]
----
{
  "style": {
    "APP_NAME": "Acme Insights",
    "DASHBOARD_HEADER_BRAND_LOGO": "brand/logo.svg",
    "--theme-light-color-primary-bg-strong": "#005eb8",
    "--theme-dark-color-primary-bg-strong": "#78b4ff"
  }
}
----

To brand a deployment made another way, mount your own file (and logo) over those paths.

== In the code

The app's own colours, type sizes and spacing are CSS variables in `src/theme/tokens.css` (`--nd-…`), with a light set and a dark set (applied under `.ndl-theme-dark`, which the app sets on `<body>`). They are built on the design system's palette, and every text colour meets WCAG AA contrast on the surfaces it's used on. `src/theme/palette.ts` holds the same values for code that can't use CSS variables, such as canvas-drawn charts; keep the two in step. `src/theme/components.css` styles the app's own components with these variables.
