= Build & Run

You need Docker, Node.js 22 and `yarn` (1.x; `corepack enable` provides it).

== The local dev stack

`dev/compose.yaml` runs everything NeoDash needs, with sample data and test users:

[source,sh]
----
docker compose -f dev/compose.yaml up -d --build
----

[cols="1,2,3",options="header"]
|===
|Service |Address |
|`neo4j` |http://localhost:7474, `bolt://localhost:7687` |Neo4j 5 Community with APOC. User `neo4j`, password `devpassword`.
|`keycloak` |http://localhost:8080 |Realm `neodash` with the test users below. Admin console: `admin` / `admin`.
|`backend` |http://localhost:3000 |NeoDash itself: the image built from this repository (UI and backend).
|`fake-llm` |– |A stand-in for an OpenAI-compatible model, so Build with AI works locally.
|`seed` |– |A one-off job that loads the sample data and example dashboards, then checks every report query.
|`neodash-legacy` |http://localhost:5005 |Unchanged NeoDash 2.4.11, for comparison.
|===

The first start takes a minute or two. Open http://localhost:3000 and sign in as `editor`, `viewer` or `nobody` (no role, so turned away); every password is `password`.

`dev/README.md` describes the sample data, the example dashboards and how to reset them.

== Working on the UI

Rebuilding the container for each change is slow. Keep the stack running and start the webpack dev server, which serves the UI with hot reload and passes `/api` and `/auth` to the backend on port 3000:

[source,sh]
----
yarn install
yarn dev        # http://localhost:5173
----

`yarn dev` also builds these docs into `docs/build`, where the dev server serves them at `/docs`; run `yarn docs` to rebuild them after editing a page.
Restart the dev server after adding or removing packages.

== Working on the backend

The backend is a separate Node.js project in `server/`:

[source,sh]
----
cd server
npm install
npm run dev        # restarts on changes
npm run typecheck
npm test
----

To run it outside Docker against the dev stack, set `PUBLIC_URL=http://localhost:3000`, `NEO4J_PASSWORD=devpassword`, `OIDC_ISSUER_URL=http://localhost:8080/realms/neodash`, `OIDC_CLIENT_ID=neodash`, `OIDC_CLIENT_SECRET=neodash-dev-secret`, `OIDC_ALLOW_INSECURE_HTTP=true` and a `SESSION_SECRET` of at least 32 characters (stop the `backend` container first, as it uses the same port).
To try a backend change in the full stack instead, rebuild its container:

[source,sh]
----
docker compose -f dev/compose.yaml up -d --build backend
----

== Building the image

The `Dockerfile` builds the UI (`yarn run build-minimal`, which also builds these docs into `dist/docs`), builds the backend, and puts both in a distroless Node.js image that runs as a non-root user:

[source,sh]
----
docker build -t neodash .
----

The image listens on port 3000 and needs the settings in xref:developer-guide/configuration.adoc[Configuration] (at least Neo4j, OIDC, `PUBLIC_URL` and a session secret). To install it on Kubernetes, see xref:developer-guide/deploy-a-build.adoc[Deploy].

`yarn build` builds just the UI into `dist/`. On its own it can't sign anyone in or run queries: it needs the backend, which serves it from `STATIC_DIR`.
