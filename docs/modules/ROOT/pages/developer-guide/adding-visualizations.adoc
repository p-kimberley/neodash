= Adding Visualizations

You can add your own visualization without diving deep into the rest of the application. Adding a setting to an existing report takes even less.

== Add a visualization

[arabic]
. Run NeoDash locally with hot reload, as in xref:developer-guide/build-and-run.adoc[Build & Run]:
+
....
docker compose -f dev/compose.yaml up -d --build
yarn install
yarn dev
....

. Create a chart component, e.g. `src/chart/list/ListChart.tsx`, that takes `ChartProps` (from `src/chart/Chart.ts`). The main properties are:
+
....
export interface ChartProps {
  records: Neo4jRecord[];                 // The query's result, as Neo4j driver records.
  selection?: Record<string, any>;        // The fields chosen in the report's footer.
  settings?: Record<string, any>;         // The report's advanced settings.
  dimensions?: Record<string, number>;    // The report's size (charts usually just fill their space).
  fullscreen?: boolean;                   // Whether the report is maximised.
  parameters?: Record<string, any>;       // The dashboard's parameter values.
  queryCallback?: (query, parameters, setRecords) => void;  // Run another query, e.g. to load more data.
  setGlobalParameter?: (name: string, value: any) => void;  // Set a dashboard parameter, e.g. on a click.
  getGlobalParameter?: (name) => string;
  updateReportSetting?: (name, value) => void;              // Change one of the report's settings.
  ...
}
....
+
`records` is the only property every chart uses. `queryCallback` runs Cypher written in the browser, which the backend allows for editors only: for viewers, a chart can only show its report's saved query.
Records reach the browser through the backend, but are rebuilt as https://neo4j.com/docs/api/javascript-driver/current/[Neo4j driver] values (integers, nodes, relationships, paths, dates…), so you can treat them as if they came from the driver.
+
A minimal example, showing every returned row as a line:
+
....
import React from 'react';
import { ChartProps } from '../Chart';
import { renderValueByType } from '../../report/ReportRecordProcessing';

const NeoListChart = (props: ChartProps) => (
  <div className='n-p-4'>
    {props.records.map((record, i) => (
      <div key={i}>{record.keys.map((key) => <span key={String(key)}>{renderValueByType(record.get(key))} </span>)}</div>
    ))}
  </div>
);

export default NeoListChart;
....
+
Use the design system's components (`@neo4j-ndl/react`) and the app's CSS variables (`src/theme/tokens.css`) rather than fixed colours, so the chart works in light and dark.

. Make it selectable: add an entry to `_REPORT_TYPES` in `src/config/ReportConfig.tsx`:
+
....
list: {
  label: 'List',
  helperText: 'Shows every returned row as a line of text.',
  component: NeoListChart,
  maxRecords: 100,
  settings: {},
},
....
+
The other entries show what else an entry can have: `selection` (field selectors in the footer), `useReturnValuesAsFields`, `withoutFooter`, and `settings` with a label, type and default for each advanced setting. Settings every report has (background colour, description, refresh…) are added automatically.

. Reload the app: your report type is in the type picker of a report's settings.

Visualizations that only some dashboards need can be packaged as an extension instead: see the advanced charts in `src/extensions/advancedcharts` and their entry in `src/extensions/ExtensionConfig.tsx`.

== Test it

Add a browser test in `dev/e2e/tests` (see xref:developer-guide/testing.adoc[Testing]): save a temporary copy of a dashboard with a report of your type, open it, and check it draws without errors. `dev/e2e/tests/helpers.mjs` has helpers for this.
