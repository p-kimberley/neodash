= Component Overview

The interface is built from these components (paths under `src/`):

....
Application                     application/Application.tsx
├── App header                  application/AppHeader.tsx
├── Start page                  dashboard/selector/DashboardSelector.tsx   (no dashboard open)
├── Dashboard                   dashboard/Dashboard.tsx
│   ├── Dashboards panel        dashboard/sidebar/DashboardSidebar.tsx
│   ├── Title and page tabs     dashboard/header/DashboardTitle.tsx, DashboardHeaderPageList.tsx
│   └── Page                    page/Page.tsx
│       └── Card (one per report)                card/Card.tsx
│           ├── Card view       card/view/CardView.tsx
│           │   ├── Header      card/view/CardViewHeader.tsx
│           │   ├── Report      report/Report.tsx  →  Chart  (chart/…, extensions/…)
│           │   └── Footer      card/view/CardViewFooter.tsx
│           └── Card settings   card/settings/CardSettings.tsx
│               ├── Header      card/settings/CardSettingsHeader.tsx
│               ├── Content     card/settings/CardSettingsContent.tsx
│               └── Footer      card/settings/CardSettingsFooter.tsx
└── Dialogs                     modal/…, and next to the components that open them
....

* *Application*: starts the app (reads who is signed in and the server's settings from `/api/me` and `/api/config`), keeps the URL in step with what's shown (`application/UrlState.ts`), and applies the light or dark appearance.
* *App header*: the dashboards panel button, the product name, save status, appearance, help and the signed-in user.
* *Start page*: the list of dashboards, shown at `/`.
* *Dashboards panel*: switches between dashboards, and creates, imports, exports and deletes them (editors).
* *Title and page tabs*: the dashboard's title, its settings and extensions, and one tab per page.
* *Page*: lays the cards out in a grid (`react-grid-layout`) that editors can rearrange and resize.
* *Card*: one report. It has two faces: the *view* (what everyone sees) and the *settings* (the query editor and report settings, for editors). A maximised card is shown in a dialog.
* *Card view header*: the drag handle (editors), the report's title and its buttons (maximise, details, refresh, edit) and its ⋮ menu (view as table, download as image, duplicate, help, delete), as the report's settings allow. The settings face has Save and Cancel; Cancel restores a snapshot of the report taken when the settings opened (`card/ReportSnapshot.ts`). "View as table" is per-card session state: the report renders its records with the table chart instead.
* *Report*: runs the report's query through the backend (`report/ReportQueryRunner.ts`), handles loading, errors and empty results, and renders the chart.
* *Chart*: draws one visualization from the query's records. See xref:developer-guide/adding-visualizations.adoc[Adding Visualizations].
* *Card view footer*: the field selectors under a chart (e.g. which property to show for each node label).
* *Card settings*: the type and database pickers, the Cypher editor, and the report's advanced settings.

== Cards, reports and charts

* The *card* places a report on the page and switches between its view and its settings.
* The *report* runs the query and handles everything around the result.
* The *chart* only renders the result it is given.

Shared building blocks used across the app are in `src/component/`: the app's `Dialog` (the design system's dialog, which also closes on a click outside it), the Cypher editor, and form fields such as `SelectField` and `SuggestInput`.
