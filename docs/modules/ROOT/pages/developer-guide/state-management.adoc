= State Management

The app's state is held in a https://redux.js.org/[Redux] store (`src/store.ts`); if you change it, be familiar with Redux's patterns (actions, reducers, selectors and thunks).

The state has three parts:

....
{
  "dashboard":      { ... },   // the open dashboard: this is what gets saved
  "application":    { ... },   // the app's own state: open dialogs, appearance, panel, unsaved changes
  "sessionStorage": { ... }    // values kept for the current session only
}
....

The store is kept in the browser's local storage (`redux-persist`, set up in `src/index.tsx`).

____
To see the whole state, download a *Debug Report* from the About dialog (Help menu in the header).
____

== Dashboard state

The `dashboard` part is the dashboard as it is saved: the backend stores this JSON as a `_Neodash_Dashboard` node, in the same format as NeoDash 2.4, so saved dashboards keep working in both. For example:

....
{
  "uuid": "5a1e5000-0000-4000-8000-000000000000",
  "title": "Sales Overview",
  "version": "2.4",
  "settings": {
    "pagenumber": 0,
    "editable": true,
    "parameters": { "neodash_region_name": "Europe" }
  },
  "pages": [
    {
      "title": "Overview",
      "reports": [
        {
          "id": "5a1e5000-0000-4000-8000-000000000005",
          "title": "Revenue",
          "query": "MATCH (o:Order) RETURN sum(o.total) AS Revenue",
          "type": "value",
          "x": 0, "y": 2, "width": 6, "height": 2,
          "selection": {},
          "settings": { "textAlign": "center" }
        }
      ]
    }
  ],
  "parameters": {},
  "extensions": { "active": true, "activeReducers": [], "styling": { "active": true } }
}
....

- `version`: the dashboard format. Older formats are upgraded when a dashboard is opened (`VERSION_TO_MIGRATE` in `src/dashboard/DashboardReducer.ts`).
- `settings`: dashboard settings, including the current page and the parameter values.
- `pages`: each page's title and reports. A report's `id` identifies it to the backend: a viewer's query request names the dashboard and report, and the backend runs the query saved there.
- `extensions`: which extensions the dashboard uses, and their state.

Keep this format compatible: dashboards saved by this version must still open in NeoDash 2.4 and the other way round. Add new report settings with a default that keeps the old behaviour.

== Application state

The `application` part is a flat object describing the app around the dashboard: whether there are unsaved changes (`draft`), which dialogs are open, the appearance (`themePreference`), whether the dashboards panel is open (`sidebarOpen`) or the start page is shown (`homeOpen`), and notifications.
It also still has upstream NeoDash's connection and standalone fields (`connection`, `standalone`, …). The backend owns the connection now, so these are no longer used for connecting.

Who is signed in and the server's settings are not in the store: `session` in `src/api/client.ts` holds the results of `/api/me` and `/api/config`, read at start-up.
