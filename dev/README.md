# Local dev stack

Everything needed to run and test NeoDash locally: Neo4j Community with mock data and example
dashboards, Keycloak with test users, and the unmodified NeoDash 2.4.11 for comparison.

```sh
docker compose -f dev/compose.yaml up -d --build
```

The first start takes a minute or two: Neo4j downloads APOC, and the `seed` job waits for Neo4j
before loading data. Follow it with `docker compose -f dev/compose.yaml logs -f seed`.

## Services

| Service          | URL                                    | Notes                                                           |
| ---------------- | -------------------------------------- | --------------------------------------------------------------- |
| `neo4j`          | http://localhost:7474, bolt://localhost:7687 | Neo4j 5.26 Community + APOC. User `neo4j`, password `devpassword` |
| `keycloak`       | http://localhost:8080                  | Realm `neodash`. Admin console: `admin` / `admin`                |
| `neodash-legacy` | http://localhost:5005                  | NeoDash 2.4.11, unchanged                                        |
| `seed`           | –                                      | One-off job; exits after loading data and checking dashboards    |

The new backend and frontend are added to this stack as they are built.

### Opening a dashboard in legacy NeoDash

Go to http://localhost:5005, choose **New dashboard**, connect with `neo4j://localhost:7687`, user
`neo4j`, password `devpassword`, then open the sidebar and load a dashboard from the database.

Or open one directly:

```
http://localhost:5005/?share&type=database&id=<uuid>&dashboardDatabase=neo4j&credentials=neo4j%3A%2F%2Fneo4j%3Adevpassword%40neo4j%3Alocalhost%3A7687&skipConfirmation=Yes
```

(Putting credentials in a URL is one of the legacy behaviours the rebuild removes; it is fine for a
local dev database.)

## Test users (Keycloak realm `neodash`)

All passwords are `password`.

| User     | Realm role       | Expected access                                        |
| -------- | ---------------- | ------------------------------------------------------ |
| `viewer` | `neodash-viewer` | Open dashboards; only their saved queries run, read-only |
| `editor` | `neodash-editor` | Everything, including free-form Cypher and saving       |
| `nobody` | none             | Rejected after login                                   |

The OIDC client is `neodash` with secret `neodash-dev-secret`. Roles appear in the
`realm_access.roles` claim of the ID token, access token and userinfo. Keycloak's issuer is
`http://localhost:8080/realms/neodash` both from the browser and from inside the compose network.

## Mock data

A fictional retailer, generated from a fixed seed in [`seed/data.mjs`](seed/data.mjs), so every
machine gets the same graph:

- 5 regions, 25 countries (ISO-2 and ISO-3 codes), 41 cities with coordinates
- 5 categories × 3 subcategories, 60 products
- 12 suppliers, 6 warehouses, supplier → warehouse → region flows
- 450 customers, ~5,400 orders (Jan 2024 – Oct 2026) with seasonality, growth, delays and returns
- 3 projects with dependent tasks (for the Gantt chart)
- The movies dataset from `scripts/docker-neo4j-initializer/movies.cypher`

Community edition has a single user database, so all of this lives in `neo4j` alongside the
dashboards.

## Example dashboards

| Dashboard                         | uuid                                   | Purpose                                                  |
| --------------------------------- | -------------------------------------- | -------------------------------------------------------- |
| Sales Overview                    | `5a1e5000-0000-4000-8000-000000000000` | Realistic layout: filters, KPIs, drill-down via table click |
| Supply Chain                      | `5c4a1000-0000-4000-8000-000000000000` | Maps, Sankey, gauge, Gantt, conditional styling           |
| Kitchen Sink — every report type  | `c0ffee00-0000-4000-8000-000000000000` | Every report type and every parameter-select type         |
| NeoDash Movies Dashboard          | `30f1e500-0000-4000-8000-000000000000` | The gallery dashboard, in the older 2.1 format (tests the upgrade path) |

They are stored as `_Neodash_Dashboard` nodes exactly as NeoDash 2.4 saves them (`user: 'seed'`).
Re-running the seed never overwrites a dashboard that already exists, so edits you make while
testing are kept.

The JSON in [`seed/dashboards`](seed/dashboards) is generated by
[`seed/build-dashboards.mjs`](seed/build-dashboards.mjs). After changing it:

```sh
node dev/seed/build-dashboards.mjs
docker compose -f dev/compose.yaml exec neo4j cypher-shell -u neo4j -p devpassword \
  "MATCH (n:_Neodash_Dashboard {user: 'seed'}) DETACH DELETE n"
docker compose -f dev/compose.yaml run --rm seed
```

Every seed run also executes each report query read-only with the dashboard's default parameters
and exits non-zero if any fail.

## Resetting

```sh
# Reload all data and dashboards (wipes the database first)
SEED_RESET=true docker compose -f dev/compose.yaml run --rm seed

# Start completely fresh
docker compose -f dev/compose.yaml down -v
```

## Secrets

`secrets/neo4j-auth.txt` holds the dev Neo4j credentials and is mounted as a Docker secret
(`NEO4J_AUTH_FILE`), the same pattern the Kubernetes deployment uses with a Secret. These are
throwaway local credentials; never reuse them elsewhere.

## Legacy quirks found while building the fixtures

Things the rebuilt UI should handle better. All of them reproduce in `neodash-legacy` with the
dashboards above.

- A style rule whose `value` is a number, rather than a string, blanks the whole dashboard
  (`value.startsWith is not a function`).
- Reports wait for every parameter in their query to be set unless the report enables
  `ignoreNonDefinedParams`, so optional filters need a hidden setting.
- Date pickers show today's date while the parameter is actually unset, so the filter looks
  active when it isn't.
- Page tabs grow a "⋯" menu on hover, which shifts the tabs to their right; clicks often open the
  menu instead of switching page.
- `?page=N` is ignored when a dashboard is opened from a share link.
- Grouped bar charts show the legend in a single colour; horizontal stacked bars colour by
  category instead of by series.
- Large single values (dates, words) overflow their card instead of scaling down.
- The empty "add report" placeholder card is laid out like a report and can push real reports
  down the page.
